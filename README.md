# LIMORA

Лёгкий нативный overlay для Codex Desktop на Windows. LIMORA показывает **оставшийся** лимит Codex рядом с полем ввода, следует за окном приложения и скрывается, когда оно закрыто или свёрнуто.

> Скриншот: место для снимка LIMORA поверх Codex Desktop.

## Возможности

- Компактное отображение, полосы и подробный режим со временем до сброса.
- Остаток вычисляется как `100 - usedPercent`; значения ограничиваются диапазоном 0–100.
- Поддержка стандартного ответа и `rateLimitsByLimitId`, включая дополнительные buckets.
- Нативное WPF окно без рамки и кнопки на панели задач; оно не активируется и в обычном режиме пропускает клики.
- Обнаружение composer через Windows UI Automation. При недоступности automation overlay размещается относительно нижней части окна Codex. Точное положение можно откалибровать перетаскиванием.
- Отслеживание окна через WinEvent hooks, без частого опроса координат; позиция учитывает текущие границы и DPI монитора.
- Иконка в системном трее, настройки, локальный автозапуск текущего пользователя и ручное обновление.
- Логи в `%LOCALAPPDATA%\LIMORA\logs\`, настройки в `%LOCALAPPDATA%\LIMORA\settings.json`.

## Требования

- Windows 11 x64.
- Codex Desktop для Windows установлен и пользователь вошёл в аккаунт.
- Для самостоятельной сборки: .NET SDK 10.0 или новее. Готовый self-contained publish не требует установленного .NET runtime.

LIMORA находит официальный `codex.exe`, вложенный в установленный пакет `OpenAI.Codex`, или использует `codex.exe` из `PATH`.

## Запуск и сборка

Запустите `dist\LIMORA.exe`. Приложение сворачивается в системный трей; для выхода используйте **LIMORA → Exit**.

Сборка Release, запуск локального набора тестов и публикация одного self-contained файла выполняются одной командой из PowerShell:

```powershell
.\build.ps1
```

Файл появится в `dist\LIMORA.exe`. Публикация рассчитана на `win-x64`; нативные runtime-компоненты single-file сборки извлекаются .NET в стандартный временный каталог при запуске.

GitHub Actions запускает тесты и публикует self-contained `LIMORA.exe` для Windows x64 на push в `main`, pull request в `main` и по ручному запуску. Готовый файл доступен в артефактах успешного workflow в течение 14 дней.

## Получение лимитов

LIMORA запускает локальный `codex app-server --stdio` из официальной поставки Codex и использует JSON-RPC методы `account/rateLimits/read` и уведомление `account/rateLimits/updated`. Уведомление запускает повторное чтение, а резервное обновление выполняется раз в 45 секунд (интервал можно изменить в настройках, допустимо 30–300 секунд). Аналитика app-server принудительно отключена.

Схема ответа меняется и может содержать несколько лимитных групп. LIMORA ищет 5-часовое и недельное окна по `windowDurationMins` во всех группах, а при их отсутствии показывает доступные primary/secondary окна с продолжительностью из ответа. Отсутствующий bucket не считается нулевым лимитом. Дополнительные поля не приводят к сбою.

## Положение overlay

По умолчанию LIMORA ищет нижнее текстовое поле в дереве Windows UI Automation Codex и размещается непосредственно над ним. Это зависит от доступности accessibility-дерева в конкретной версии Codex. Если поле не обнаружено после нескольких ограниченных попыток, используется сохранённая привязка к окну.

В меню трея выберите **Calibrate position**, перетащите индикатор и отпустите мышь: смещение сохранится относительно окна Codex, в DIP. Режим **Position → Automatic** снова включает поиск composer. Ручные якоря BottomCenter, BottomRight и BottomLeft доступны в меню и настройках.

## Приватность и безопасность

- LIMORA не читает и не копирует файлы авторизации, токены, cookies или заголовки.
- LIMORA не внедряется в Codex, не модифицирует его файлы и не устанавливает DLL hooks в процесс. WinEvent hooks наблюдают только системные события окон.
- Настройки и диагностика остаются локально. LIMORA не добавляет телеметрию и отключает аналитику своего app-server.
- Для получения актуального usage сам официальный Codex app-server обращается к сервису OpenAI от имени уже настроенного Codex. LIMORA не отправляет usage сторонним сервисам. Подробные ответы RPC и stderr в журнал не записываются.
- Приложение не требует прав администратора. Автозапуск использует только раздел `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.

## Устранение неполадок

- **Codex offline** — откройте окно Codex Desktop. Overlay скрывается, пока подходящее окно не найдено.
- **Limits unavailable** — проверьте вход в Codex и подключение к сети. LIMORA использует установленную версию app-server; совместимость RPC может измениться при обновлении Codex.
- **Overlay расположен неверно** — попробуйте **Calibrate position**. Автоматический поиск зависит от того, предоставляет ли текущая версия Codex composer в UI Automation.
- **Проверить диагностику** — файлы `limora-YYYY-MM-DD.jsonl` находятся в `%LOCALAPPDATA%\LIMORA\logs\`. Секреты авторизации туда не включаются.

## Структура

```text
LIMORA/
├── App.xaml(.cs)                       запуск и время жизни приложения
├── Models/                             настройки и модели usage
├── Services/Codex/                     app-server, поиск CLI, разбор ответа
├── Services/Settings/                  локальные настройки и автозапуск
├── Services/Windows/                   отслеживание окна, позиция, tray
├── Infrastructure/                     Win32 API и локальное логирование
├── ViewModels/                         текст и цвет индикатора
└── Views/                              WPF overlay и окно настроек
Tests/                                  локальные поведенческие проверки
build.ps1                               Release publish win-x64
```

## Протокол и источники

- App-server README и контракт протокола: [openai/codex — app-server](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md).
- При разработке локальная версия Codex `0.162.0-alpha.17.2` подтвердила наличие обоих методов и multi-bucket схемы через `codex app-server generate-json-schema --experimental`. Эта схема является источником для сборки; отдельная копия сгенерированной схемы в LIMORA не хранится.
